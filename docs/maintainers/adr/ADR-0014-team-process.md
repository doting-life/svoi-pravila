# ADR-0014 — Командный процесс: задачи в GitHub, единые правила для всех исполнителей

Статус: принято · 2026-10-11 · Автор: Claude (CTO), по решению владельцев

## Контекст
До 11.10 в проекте был один исполнитель (Cursor). Промпты и отчёты жили только в чате владельца с CTO, правила исполнителя — в `.cursor/rules/`. В команде два владельца с равными правами и разные инструменты: Cursor и GitHub Copilot (локально, режим агента). Copilot не читает `.cursor/rules/`; второй участник не видит очередь задач; каждый отчёт приходилось пересылать вручную.

Решения владельцев 11.10:
- репозиторий остаётся публичным;
- оба владельца — с правами владельца в GitHub; сервер прода и релизы — только у одного из них;
- у каждого исполнителя свой тестовый бот и свой ключ GigaChat с дневным лимитом;
- CTO подключён к репозиторию (чтение; запись — через приложение Claude для GitHub).

## Решение
1. **Задача — GitHub Issue** по шаблону «Task (CTO)», заголовок `NNNN — …`, метка `task`. Отменяет правило 03.10 «промпты только в чате».
2. **Работа — Pull Request** из ветки `task/NNNN-slug`; **отчёт — описание PR** по шаблону; исправления после ревью — в том же PR (`NNNN-a`), новый отчёт — комментарием.
3. **Вердикт CTO — ревью PR**: `ACCEPT` или `CHANGES REQUIRED` с промптом. Слияние — squash, только владелец и только после ACCEPT и зелёного CI.
4. **Вопросы и предложения команды** — Issue «Proposal» или комментарий с меткой `needs:cto`; решения владельцев — метка `needs:owner`.
5. **Правила исполнителей — один источник для всех инструментов:** `AGENTS.md` в корне и в областях (`backend/AGENTS.md`, `miniapp/AGENTS.md`). Cursor и Copilot читают `AGENTS.md`, включая вложенные; агент загружает правила только той области, где работает. `.cursor/rules/` удалены.
6. **Защита `master` средствами GitHub:** только через PR; обязательные проверки CI; только squash; без force-push и удаления; CODEOWNERS — команда `builders` организации (без личных логинов). Автор PR не одобряет свой PR — его одобряет второй владелец после ACCEPT CTO.
7. **Конфиденциальность публичного репозитория:** в коде, коммитах, ветках, Issue, PR и документах — никаких имён людей, логинов, e-mail, локальных путей, названий компаний, доменов и IP прода, секретов, пользовательских данных и деловых материалов. Только роли. Коммиты CTO подписаны как `Claude (CTO)`.
8. **Экономия токенов закреплена правилами:** Issue самодостаточна; исполнитель читает только указанные разделы; проверки по области изменений; полный `make ci` — один раз в хуке перед push; отчёт — короткий шаблон; живые вызовы LLM — только с бюджетом в Issue.

## Отклонено
- **Buzz (Block)**: проект сам называет себя незавершённым; подтверждение действий агентов не готово; связи с GitHub нет — два источника правды. Пересмотр после появления этих возможностей.
- **Облачный агент Copilot** (Issue назначается на Copilot): не проходит наш хук перед push, требует отдельной настройки Postgres/Valkey в Actions и дополнительных запросов. Пересмотр для мелких изолированных задач позже.
- **Отдельные чаты с Claude у каждого участника**: решения расходятся; единая история — в GitHub.

## Последствия
- Список CTO-путей — один файл `.github/cto-owned-paths`; его читают и правила (`AGENTS.md`), и проверки CI.
- Ссылки на `.cursor/` в коде CI (`scripts/ownership_guard.sh`, `scripts/ci_scope.py`, их тесты) и в `backend/README.md` обновляются задачей исполнителя; до неё CTO-пути `backend/AGENTS.md`, `miniapp/AGENTS.md` и `.github/` не защищены проверкой владения.
- Для CODEOWNERS владельцы создали в организации команду `builders` с правом записи.
- Пока приложение Claude для GitHub не установлено, CTO читает GitHub, а вердикты передаёт через владельца.
