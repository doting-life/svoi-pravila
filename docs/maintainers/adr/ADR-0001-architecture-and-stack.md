# ADR-0001 — Архитектура и стек

Статус: принято · 2026-10-03 · Автор: Claude (CTO)

## Контекст
Рабочий MVP за 12 дней, функционально полный продукт за 62 дня; платформа — Telegram (бот + мини-приложение); данные особой чувствительности; команда сильна в Python/FastAPI и React.

## Решение
1. Hexagonal-архитектура: `domain` → `application` (порты) → `adapters`/`api` → `bootstrap`. Границы проверяются import-linter.
2. Один Python-сервис (FastAPI + aiogram) принимает webhook Telegram и обслуживает API mini-app. Обработка обновлений — фоновые задачи процесса с дедупликацией и graceful shutdown. Очередь задач не вводим, пока нагрузка или надёжность этого не потребуют (пересмотр в Спринте 4 по результатам нагрузочного теста).
3. Python 3.13, uv, Pydantic v2, SQLAlchemy 2 async + asyncpg, Alembic, PostgreSQL 18, Valkey.
4. LLM — порт `LLM`, первый адаптер — GigaChat SDK.
5. Mini-app — статическое SPA на Vite + React + TypeScript; контракты из OpenAPI.
6. Доставка — Docker + docker compose + Caddy на OVH VPS (ADR-0003).

## Альтернативы
- Next.js для mini-app — отклонено: SSR не нужен внутри WebView, лишняя серверная поверхность.
- LangChain — отклонено: тяжёлая абстракция, нам нужен один тонкий порт.
- Отдельный воркер с очередью с первого дня — отклонено до появления измеримой потребности.
- Python 3.14 — отложено до поддержки всеми зависимостями (SDK GigaChat — до 3.13).

## Последствия
Домен и сценарии тестируются без Telegram и LLM. Смена LLM-провайдера — новый адаптер + прогон eval.
