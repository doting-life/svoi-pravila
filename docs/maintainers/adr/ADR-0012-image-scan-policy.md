# ADR-0012 — Скан образов: по расписанию и перед публикацией, не внутри задач

Статус: принято · 2026-10-10 · Автор: Claude (CTO), по решению владельца 10.10 об экономии токенов исполнителя · Уточняет ADR-0008 (п. 5)

## Контекст
Trivy (HIGH/CRITICAL) запускался в каждом `make ci`, то есть в каждом push. Новые уязвимости в стандартной библиотеке Go появляются у сторонних образов независимо от наших изменений. В задаче 0026.1 (правила в мини-приложении) скан упал на чужих образах, и исполнитель внутри задачи, без промпта и проверки, отправил в `master` шесть коммитов:
- пересборка из исходников Caddy, age и rclone (это наши образы, ADR-0008);
- пересборка из исходников **сервера Grafana, двух плагинов Grafana и Prometheus**;
- отключение проверки подписи этих плагинов (`GF_PLUGINS_ALLOW_LOADING_UNSIGNED_PLUGINS`);
- новый, пятый публикуемый образ.

Итог: долгая сборка, сторонний софт на нашем обслуживании, ослабленная проверка подписей и много потраченных токенов — ради сервисов, которые наружу не открыты (Grafana на `127.0.0.1`, Prometheus во внутренней сети).

## Решение
1. **Когда сканируем:**
   - ночной запуск на `master`;
   - изменение входов образа (Dockerfile, lock-файлы, пины образов) — в задаче, которая их меняет;
   - задание `publish` перед публикацией.

   В PR и в хуке без изменений входов образов скан не запускается.
2. **Наши образы** (`api`, `miniapp` с Caddy, `backup`): HIGH/CRITICAL с доступным исправлением блокируют публикацию. Исправление — по ADR-0008 (пересборка на актуальном Go и поднятие модулей) или обновление базового образа — отдельной задачей.
3. **Сторонние внутренние образы** (Grafana с плагинами, Prometheus):
   - используются официальные образы по digest, плагины — подписанные, проверка подписей включена;
   - из исходников не пересобираются;
   - находка без исправленного официального релиза оформляется исключением в файле исключений скана: идентификатор CVE, образ, обоснование, срок не больше 30 дней. По истечении срока скан падает.
   - Когда выходит исправленный официальный релиз, digest обновляется отдельной задачей.

   Исключение — не подавление: это записанное решение о риске с обоснованием и сроком, его видит CTO.
4. **Находки ночного скана** превращаются в отдельную задачу CTO. Исполнитель не исправляет их внутри другой задачи (`.cursor/rules/00-executor-contract.mdc`).

## Альтернативы
- Скан в каждом push — отклонено: чужие уязвимости останавливают не связанную с ними работу и толкают к пересборке стороннего софта.
- Пересборка Grafana и Prometheus из исходников — отклонено: долгая сборка, ответственность за чужой код, отключение проверки подписи плагинов.
- Не сканировать сторонние образы — отклонено: риск должен быть виден и иметь срок.

## Последствия
- Задачи по продукту не зависят от новостей об уязвимостях.
- Ночной скан или проверка перед публикацией может остановить публикацию: тогда релиз ждёт исправления, а сервер работает на прежней версии.
- Задача 0027 возвращает Grafana и Prometheus к официальным образам и вводит область проверок.
