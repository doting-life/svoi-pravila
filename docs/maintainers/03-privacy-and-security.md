# Приватность и безопасность

Владелец документа: Claude (CTO). Исполнители этот документ не редактируют.
Редакция: 1.2 · 2026-10-15 (ред. 1.2 — внешняя Grafana и алерты, ADR-0017)
Это инженерная модель требований, не юридическое заключение. Юридическое оформление релиза (финальные тексты согласий, политика обработки данных, уведомления регуляторов, юрисдикция хранения) — зона выпускающей стороны (ADR-0003). Продукт обязан технически позволять его выполнить.

---

## 1. Принципы
1. **Только явное действие.** Обрабатывается только текст, который пользователь сам передал боту: inline-запрос, пересланное или вставленное сообщение, ввод в mini-app. Бот не читает чаты.
2. **Не храним переписку.** Черновики, входящие сообщения и ответы модели живут только в памяти обработки запроса.
3. **Минимизация данных третьих лиц.** Метаданные отправителя пересланного сообщения отбрасываются на границе адаптера; контакт в своде — псевдоним, заданный пользователем.
4. **Шифрование чувствительного.** Свод правил и метки контактов шифруются на уровне приложения (envelope encryption, ключ на пользователя / на пару).
5. **Удаление по-настоящему.** Удаление аккаунта — немедленное уничтожение ключа данных и записей; бэкапы ротируются, и восстановление удалённых пользователей запрещено runbook-ом.
6. **Переносимость и контроль.** Все данные — на нашем сервере и в наших бэкапах; внешних SaaS для логов, ошибок и аналитики нет. Продукт разворачивается в любой юрисдикции по runbook.

## 3. Согласия (механизм)
- Онбординг до первого сценария: подтверждение 18+ → экран согласия на обработку ПДн → **отдельный** экран согласия на обработку специальной категории (сведения о частной и интимной жизни в передаваемых текстах) → краткое объяснение «что мы храним и чего не храним» → предупреждение о пометке «via @bot» при вставке через inline.
- Каждое согласие — отдельное явное действие (кнопка), не совмещённое с другими документами.
- Тексты согласий в репозитории — черновики; выпускающая сторона заменяет их финальными без изменения кода (тексты — версионируемые данные).
- Сохраняется: тип, версия текста, SHA-256 текста, время, канал. Тексты версий хранятся в репозитории.
- Отзыв: команда и кнопка в mini-app; после отзыва сценарии недоступны, данные удаляются в соответствии с политикой.
- Изменение текста согласия = новая версия = повторный запрос согласия.

## 4. Права пользователя
- `/export` — выгрузка своих данных (контакты, правила, согласия) в читаемом виде, в личку.
- `/delete` — удаление аккаунта с подтверждением: crypto-shredding + удаление записей + выход из всех пар (партнёр видит, что свод больше не общий; правила, сформулированные партнёром, остаются у него — D-7).

## 5. Модель угроз (STRIDE, сокращённо)

| Угроза | Вектор | Контроль |
|---|---|---|
| Подделка webhook | запросы на endpoint не от Telegram | secret token, сравнение за постоянное время, отдельный неугадываемый путь |
| Подделка/повтор `initData` | вызов API mini-app от чужого имени | HMAC-проверка, свежесть `auth_date`, без доверия к данным клиента вне `initData` |
| IDOR | доступ к чужому контакту/правилу/паре по id | проверка членства в сценарии; непоследовательные идентификаторы (UUIDv7); тесты на каждый эндпоинт |
| Подбор приглашений | перебор токенов | 128 бит энтропии, хранится хэш, одноразовость, TTL, rate limit |
| Prompt injection | инструкции во входящем сообщении собеседника | разделение данных и инструкций, structured output, проверка вывода |
| Утечка через логи | тексты в логах/исключениях | процессор редактирования, тест-«канарейка»: заведомый маркер в тексте не должен появиться ни в одном лог-событии |
| Исчерпание бюджета LLM | спам inline-запросами | отмена устаревших, квоты, rate limit, алерты 80 % и 100 % дневного бюджета и всплеска расхода (ADR-0017) |
| Слежка партнёра | использование общего свода для контроля | партнёр видит только общий свод; личные контакты и предложения приватны; выход из пары в один шаг |
| Злоупотребление продуктом | генерация манипуляций, угроз | слой безопасности ответов, eval-кейсы на отказ |
| Компрометация сервера | доступ к БД | шифрование C2, KEK вне БД, минимальные права, обновления, сканирование образов |
| Цепочка поставок | уязвимые/вредоносные пакеты | lock-файлы, `pip-audit`, сканирование образа, новые зависимости — только по решению CTO |
| Подбор пароля Grafana | перебор на поддомене Grafana | защита от перебора по имени и IP (IP передаёт Caddy), без анонимного входа, регистрации и базовой аутентификации API, длинные случайные пароли (ADR-0017) |
| Произвольные запросы через Grafana | Viewer шлёт свой SQL или PromQL в источник данных | роль БД видит только агрегаты (не ПДн), только чтение, тайм-аут 10 с, лимит 5 соединений; метки Prometheus — только перечисления; тайм-аут PromQL 30 с; интеграционный тест прав роли |
| Уязвимость Grafana | известная CVE в образе, доступном из интернета | без исключений скана, ежедневный скан, Grafana без выхода в интернет и без доступа к `api`, `valkey`, `usage_events` |
| Утечка через алерты | данные в тексте уведомления | только статические аннотации и метки-перечисления; отдельный бот уведомлений, токен и чат — файлы на сервере |

## 6. Гейты безопасности в CI
`gitleaks` (секреты), правила `ruff` группы `S` (безопасность), `pip-audit`, сканирование образа (trivy) с порога «high», проверка, что миграции не создают колонок для текстов переписки, тест-«канарейка» для логов.

## 7. Инциденты
- Runbook реагирования на инцидент в `deploy/`: изоляция, ротация ключей и секретов, оценка затронутых данных, восстановление.
- Уведомление регуляторов и пользователей — зона выпускающей стороны; runbook даёт ей необходимые технические данные.
- Ответственный за техническое реагирование — владелец (ops); техническая часть runbook — CTO.

## 8. Безопасность пользователей (продуктовая)
- Кризисные сигналы (угроза жизни, насилие) → вместо генерации — бережный ответ и контакты помощи из каталога по локали (каталог — данные, проверяются перед релизом).
- Отказ: манипуляция, газлайтинг, угрозы, давление, слежка, преследование.
- «Расшифровать» говорит гипотезами («возможно, человек имеет в виду…»), не приписывает намерения.
- Продукт не позиционируется как психотерапия; в онбординге — это явно.
