# ADR-0015 — Три режима «Проверить / Мягче / Твёрже», один сценарий переписывания, контакт только явный

Статус: принято · 2026-10-12 · Автор: Claude (CTO), по итогам интервью с пользователями (8 интервью, тест на реальных сообщениях) и решений владельцев 12.10

## Контекст
Интервью показали три задачи пользователя: быстро и грамотно написать важное сообщение своими словами; понять чужое сообщение; иногда смягчить, сохранив позицию. Общий барьер — текст не должен звучать как ИИ и не должен быть «не моим».

Проверка кода `7520605` показала причины замечаний:
- **Чужой контекст в inline — следствие проекта, а не случайный дефект.** Inline и кнопка над результатами берут «активный контакт» из профиля (`users.active_contact_id`; его ставит мини-приложение), его отношение и правила; кнопка подписана его именем. Правило, созданное из подсказки после расшифровки, — тоже правило этого контакта, поэтому в inline попадают слова прошлой расшифровки.
- **Смысл теряется в промпте.** Промпты soften/help_say требуют во всех трёх слотах «убрать атаку, сарказм и обобщения» — модель смягчает и переворачивает просьбу, добавляет «терапевтические» формулы.
- **«Проверить» — не степень тона.** Слоты `gentle / balanced / firm` (enum `Firmness`) зашиты в схему ответа модели, БД, OpenAPI, мини-приложение и каталог тоновых подсказок.

## Решение
1. **Варианты.** Новый тип `VariantKind`: `check` («Проверить» — исправить орфографию и пунктуацию, слова, тон, мат и регистр автора не менять), `softer` («Мягче» — убрать резкость, претензия остаётся), `firmer` («Твёрже» — прямо и коротко, без извинений). `Firmness` удаляется. Порядок показа везде: Проверить, Мягче, Твёрже.
2. **Один сценарий переписывания.** `soften` и `help_say` объединяются в сценарий `rewrite`: один промпт, один вызов модели, три слота в одном JSON. Цель (`decline`, `set_boundary`, `admit_fault`, `reconnect`) — необязательный параметр только в мини-приложении; по умолчанию не выбрана. Префиксы целей в inline удаляются.
3. **Контакт только явный.** Понятия «активный контакт» нет. Контакт и его правила применяются только в мини-приложении и только к тому запросу, где пользователь выбрал контакт на экране (`contact_id` в теле запроса). Inline никогда не использует контакт, отношение, правила и состояние мини-приложения: отношение `other`, правил нет, кнопка над результатами — «Без контакта». Удаляются `users.active_contact_id`, `POST /contacts/{id}/activate`, `set_active_contact`, имя контакта в кнопке inline, партнёр в сессии, открытой из inline.
4. **Правила** применяются к `softer` и `firmer`; `check` от правил не зависит.
5. **Типографика человека** — правило домена для каждого текста, который пользователь может отправить (варианты переписывания и варианты ответа после расшифровки): если в черновике нет длинного/короткого тире, то « — » → «, », тире между цифрами → «-», прочие «—»/«–» → «-»; «…» → «...». Если автор сам ставит тире — его текст не меняем.
6. **Политика вариантов** — проверка кодом, не только промптом: стоп-фразы «терапевтического» языка (версионируемый список в домене), длина (`softer` ≤ max(черновик × 1,2; черновик + 6 слов), `firmer` ≤ черновик × 1,2), объём правки `check` ≤ 15 % символов, сохранение «ты/вы». В eval — гейт релиза; на проде — счётчик нарушений без текста (C0). Перегенерации на проде нет.
7. **Модель** не меняется (решение владельцев 12.10: сравнение с GigaChat Pro разницы не показало): `rewrite` работает на модели, заданной переменной окружения. Приёмка нового промпта — eval-кейсы из интервью на этой модели.
8. **Онбординг** — один экран при первом открытии; флаг «показан» хранится в Telegram `CloudStorage` (хранилище бота на пользователя, синхронизируется между устройствами), без БД. «Попробовать на примере» делает живой вызов модели.
9. **Аналитика:** `variant_firmness` в событиях становится `variant_kind`; `scenario` — `rewrite`/`decode`; текст не хранится (ADR-0002).

## Последствия
- Inline больше не пишет тоновые сигналы (выбор не к кому привязать). D-6 сужается: сигнал тона пишет только выбор в мини-приложении при явно выбранном контакте; шаблоны подсказок — для `softer` и `firmer`.
- Миграции: `gentle` → `softer`, `firm` → `firmer`, строки с `balanced` удаляются (тоновые сигналы и тоновые подсказки); `soften`/`help_say` → `rewrite` в событиях использования; удаление `users.active_contact_id`.
- ADR-0013: кнопка «Для: {имя} · без подписи» и «Отправить {имя}» из сессии, открытой из inline, отменяются; «Отправить {имя}» остаётся на экране мини-приложения при явно выбранном контакте-партнёре.
- Путь «Вставить» после расшифровки (подготовленные результаты) остаётся: это явное действие пользователя.

## Отклонено
- Фильтровать контакт только в inline, оставив активный контакт в профиле, — состояние мини-приложения продолжит протекать в другие поверхности.
- Отдельный вызов модели на каждый вариант — тройная задержка и расход.
- Перегенерация при нарушении политики на проде — удваивает задержку; сначала данные со счётчика.
- Подключение DeepSeek сейчас — новый провайдер без доказанной пользы на текущем этапе.
