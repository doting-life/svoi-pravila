# ADR-0002 — Переписка не хранится; свод правил шифруется на уровне приложения

Статус: принято · 2026-10-03 · Автор: Claude (CTO)

## Контекст
Тексты содержат сведения о частной и интимной жизни пользователя и третьих лиц. Обещание продукта — «обрабатываем только переданный текст». Свод правил — ценнейшие и чувствительнейшие данные.

## Решение
1. Черновики, входящие сообщения и ответы модели не сохраняются ни в БД, ни в логах, ни в метриках. Исключение — prepared result для «Вставить в чат»: зашифрован, одноразовый, TTL ≤ 10 минут.
2. Обучение правил — только по метаданным (какой вариант выбран, жёсткость, сценарий) и по явно подтверждённым пользователем формулировкам правил.
3. Данные класса C2 шифруются AES-256-GCM: DEK на пользователя (и на пару), обёрнутый KEK из секретов сервера; AAD привязывает шифртекст к записи.
4. Удаление аккаунта — crypto-shredding (уничтожение DEK) + удаление записей.

## Последствия
- Отладка качества ответов возможна только на синтетическом eval-наборе — это осознанная цена.
- Поиск по тексту правил на стороне БД невозможен; при росте сводов — ранжирование в приложении или эмбеддинги, вычисляемые на лету (отдельный ADR).
