# ADR-0011 — Продакшен на VPS: образы из CI, релиз по digest, TLS на Caddy, шифрованные бэкапы

Статус: принято · 2026-10-07 · Автор: Claude (CTO), по приоритету владельца 07.10

## Контекст
Владелец решил выйти в продакшен сразу после нового облика мини-приложения. По ADR-0005 на сервере работают те же образы, что прошли проверки. Cursor не имеет доступа к серверу: всё серверное он готовит как код и runbook, выполняет владелец.

## Решение
1. **Образы.**
   - После зелёного CI на `master` отдельное задание публикует проверенные образы (api, мини-приложение с Caddy, Grafana, backup) в GHCR с тегом по коммиту.
   - Сервер разворачивает их только по digest. Сервер ничего не собирает.
2. **Релиз и откат.** `deploy/release.sh <sha>` на сервере:
   - preflight;
   - pull;
   - бэкап перед миграцией;
   - одноразовая миграция;
   - `up --wait`;
   - проверки: готовность API, webhook Telegram, мини-приложение с CSP и HSTS.

   Digest каждого релиза записывается на сервере. Откат — тот же скрипт с предыдущим `sha` (миграции только вперёд-совместимые).
3. **Периметр.**
   - Наружу открыты только 80 и 443: Caddy из образа мини-приложения с автоматическим TLS (ACME), HSTS и прежней строгой CSP.
   - Webhook Telegram — по секретному пути с секретным токеном.
   - Postgres, Valkey и метрики доступны только во внутренних сетях.
   - Grafana слушает только `127.0.0.1` сервера, доступ к ней — через SSH-туннель.
4. **Секреты.**
   - Один файл окружения на сервере с правами 600; в репозитории его нет.
   - KEK и pepper генерируются на сервере один раз.
   - Владелец хранит их копию офлайн: потеря KEK означает потерю данных.
5. **Бэкапы.**
   - Ежедневный `pg_dump` шифруется `age` на открытый ключ; закрытый ключ хранится только у владельца, офлайн.
   - Зашифрованная копия отправляется в OVH Object Storage, хранение 30 дневных и 12 месячных копий.
   - Расписание — systemd-таймер хоста.
   - Восстановление проверяется скриптом в изолированный контейнер. Выполняет владелец с закрытым ключом, ежемесячно.
6. **Сервер.**
   - Ubuntu LTS, идемпотентный скрипт подготовки:
     - пользователь для развёртывания;
     - SSH только по ключу, без root;
     - ufw: 22, 80, 443;
     - автоматические обновления безопасности;
     - Docker из официального репозитория;
     - ротация логов.
7. **Репетиция.** Продакшен-конфигурация поднимается локально и в CI с локальным TLS (`prod-smoke`), чтобы ошибки находились до сервера.

### Дополнение от 08.10 (решение владельца)
Платное объектное хранилище на старте не используется.
- Обязательная копия бэкапов — локальный каталог на сервере `/srv/svoi-pravila/backups`: те же шифрование `age`, имена и сроки хранения.
- Внешняя копия необязательна: подключается любым remote rclone через файл `/etc/svoi-pravila/backup-remote/rclone.conf` (уточнено в 0023-b: контейнер бэкапа видит только этот каталог, без остальных секретов). Без файла бэкап работает только локально и пишет предупреждение.
- Риск принят владельцем: при потере сервера теряются и копии. Смягчение — ручное копирование месячных копий на компьютер владельца (RUNBOOK).

### Дополнение от 08.10 (2): целевая ОС — Debian 13
Владелец поднял VPS на Debian 13 (trixie). Поддерживается одна ОС, чтобы скрипт подготовки не ветвился:
- `bootstrap.sh` принимает только Debian 13 и останавливается на любой другой ОС;
- Docker ставится из официального репозитория Docker для Debian, с проверкой отпечатка ключа;
- пользователь `deploy` создаётся с UID/GID 1500 (контейнер бэкапа работает от того же UID); если владелец создал его заранее с этими UID/GID, скрипт его принимает;
- после настройки SSH скрипт проверяет итоговые значения через `sshd -T`, чтобы файлы провайдера в `sshd_config.d` не оставили вход по паролю или для root.

Ubuntu 24.04 больше не поддерживается. Переход на другую ОС — новым дополнением.

### Дополнение от 08.10 (3): без проксирующего CDN
TLS завершается только на нашем сервере (Caddy). DNS-запись домена мини-приложения указывает прямо на VPS; проксирование CDN с расшифровкой трафика (например, Cloudflare в режиме «Proxied») не используется: такой прокси видел бы тексты пользователей, которые проходят через API, и становился бы ещё одним обработчиком данных. В Cloudflare запись ставится в режим «DNS only».

## Альтернативы
- Сборка на сервере — отклонено: на сервер попадали бы не проверенные образы.
- Бэкапы без шифрования на стороне сервера — отклонено (ADR-0002).
- Kubernetes или PaaS — избыточно для одного сервера.

## Последствия
- У владельца есть runbook на русском: первичная настройка, релиз, откат, бэкап и восстановление, ротация секретов, логи, туннель к Grafana.
- Выбор юрисдикции хранения и юридическое оформление остаются за выпускающей стороной (ADR-0003).
