# ADR-0017 — Grafana на поддомене для внешнего просмотра, алерты в Telegram

Статус: принято · 2026-10-15 · Автор: Claude (CTO), по решениям владельцев 15.10. Меняет ADR-0011 п. 3 (периметр) и ADR-0012 п. 3 (сторонние образы); закрывает пункты плана 0020.3 (алерты) и 0038 (образы Grafana и Prometheus).

## Контекст
1. **Доступ для ментора.** Ментору внешней программы нужен постоянный просмотр метрик продукта и сервиса. Сейчас Grafana слушает только `127.0.0.1` сервера, вход — через SSH-туннель (ADR-0011 п. 3). Выдать ментору SSH-доступ к серверу нельзя.
2. **Viewer в Grafana — не граница доступа.** Любой пользователь, у которого есть право запроса к источнику данных (в том числе роль Viewer), может отправить через Grafana **произвольный SQL** в PostgreSQL и **произвольный PromQL** в Prometheus. Настоящая граница — права роли БД и состав меток Prometheus. Пример цены ошибки: в марте 2026 уязвимость Grafana (CVE-2026-27876) давала Viewer запись файлов на сервер через SQL-выражения.
3. **Исключения скана держатся на старом периметре.** Временные исключения для Grafana в `ops/trivy-exceptions.yaml` обоснованы фразой «Grafana слушает только 127.0.0.1». Для Grafana, доступной из интернета, это обоснование неверно.
4. **Нет уведомлений о сбоях** (реестр долга, п. 5): о падении прода, исчерпании бюджета LLM, сбое бэкапа или заполнении диска владельцы узнают от пользователей.
5. **Grafana имеет выход в интернет** через сеть `grafana_edge`. Сеть нужна только для публикации порта на хост. Сервису, открытому снаружи, выход в интернет не нужен: при подделке серверных запросов (SSRF) он стал бы каналом наружу.

## Решение

### 1. Grafana — на отдельном поддомене домена мини-приложения
- Адрес — отдельное имя `SP_GRAFANA_DOMAIN` (поддомен домена мини-приложения). Оно задаётся в env-файле сервера, в репозитории его нет. DNS-запись указывает прямо на VPS в режиме «DNS only» (ADR-0011, дополнение 3).
- Подпуть на домене мини-приложения отклонён. Grafana и мини-приложение оказались бы в одном origin: строгую CSP мини-приложения (без `unsafe-inline` и `unsafe-eval`) пришлось бы ослабить на части путей, а код Grafana работал бы в origin, которому доверяет Telegram WebView.
- TLS завершает тот же Caddy (образ мини-приложения), сертификат — ACME. Caddy проксирует на `grafana:3000` по новой внутренней сети `grafana_proxy` (`internal: true`), в которую входят только Caddy и Grafana.
- **SSH-туннель убирается:** у Grafana нет опубликованных портов на хосте, сеть `grafana_edge` удаляется из продовой конфигурации. Grafana остаётся только во внутренних сетях (`observability`, `grafana_proxy`) и не имеет выхода в интернет. Вход один — через домен. Локальный `compose.yaml` разработчика не меняется.
- Принятое следствие: если Caddy не работает, Grafana недоступна. В этом случае не работает и сам продукт, а данные Prometheus и PostgreSQL сохраняются.

### 2. Вход и права
- Анонимный доступ, регистрация, базовая HTTP-аутентификация API, снимки (snapshots) и публичные (shared) дашборды выключены. Встраивание во фреймы запрещено.
- Вход — по логину и паролю Grafana. Защита от перебора Grafana включена по имени пользователя и по IP. Реальный IP клиента передаёт Caddy, присланный клиентом `X-Forwarded-For` Caddy не принимает.
- Включена собственная CSP Grafana. Cookie — `Secure`, `SameSite=Strict`, `root_url` и `enforce_domain` — по `SP_GRAFANA_DOMAIN`.
- **Ментор — личный аккаунт с ролью Viewer** в основной организации. Аккаунт создаёт владелец (релизы и сервер) по RUNBOOK. Пароль передаётся ментору отдельно от логина. Доступ отзывается отключением аккаунта. Аккаунты не создаются из файлов в репозитории.
- Домашний дашборд — «Аналитика». Ментор видит оба провиженных дашборда («Аналитика», «Эксплуатация»), не может их менять и не имеет Explore.

### 3. Граница данных — роль БД и метки, а не роль Grafana
- Роль Grafana в PostgreSQL (`SP_GRAFANA_DB_USER`, член `svoi_analytics_read`) читает только три таблицы агрегатов (как и раньше). Дополнительно шаг `migrate` при каждом релизе фиксирует для неё:
  - `default_transaction_read_only = on`;
  - `statement_timeout = 10s`;
  - `idle_in_transaction_session_timeout = 30s`;
  - `CONNECTION LIMIT 5`.

  Источник данных Grafana ограничен тем же числом соединений.
- Интеграционный тест подтверждает от имени этой роли: нет доступа к `usage_events`, таблицам пользователей, правил и контактов; DDL и запись запрещены; `SET ROLE` в другие роли невозможен; долгий запрос прерывается по тайм-ауту.
- Prometheus: метки — только из перечислений домена (§8 архитектуры, без изменений). Тайм-аут запроса — 30 с.
- Пункт плана 0022 (раздельные роли `migrate` / `api`) остаётся отдельной задачей. Эта ADR фиксирует только границу роли Grafana.

### 4. Сторонние образы, доступные из интернета, — без исключений (меняет ADR-0012 п. 3)
- **Grafana доступна из интернета**, поэтому временные исключения скана для неё запрещены: HIGH/CRITICAL с исправлением блокируют публикацию так же, как для наших образов. Если в последнем официальном релизе Grafana есть такая находка, Grafana не открывается снаружи до выхода исправленного релиза. Пересборка из исходников по-прежнему запрещена (ADR-0012).
- **Внутренние сторонние образы** (Prometheus, Alertmanager, node_exporter) — по ADR-0012 п. 3 без изменений. Обоснование каждого исключения учитывает, что Prometheus теперь косвенно доступен аутентифицированным пользователям Grafana через PromQL.
- Ночной скан `master` — **ежедневно**, как записано в ADR-0012 п. 1 (в CI сейчас еженедельно).

### 5. Алерты: правила Prometheus → Alertmanager → Telegram
- Правила — в репозитории (`ops/prometheus/rules/`), с модульными тестами `promtool test rules` в CI. Конфигурация Alertmanager проверяется `amtool check-config`.
- Доставка — официальный Alertmanager (без внешних SaaS, R2) в **отдельный бот уведомлений** в закрытый чат владельцев. Токен продуктового бота в Alertmanager не передаётся. Токен бота уведомлений и id чата — файлы на сервере (`bot_token_file`, `chat_id_file`), в репозитории и env приложения их нет. Alertmanager — единственный сервис наблюдаемости с выходом в интернет (сеть `egress`).
- Grafana-алертинг отклонён: правила Prometheus проверяются тестами в CI, а Grafana остаётся без выхода в интернет.
- **Метрики хоста** — официальный node_exporter во внутренней сети `metrics`, только нужные коллекторы (CPU, память, файловые системы, диски, нагрузка, сеть без адресов устройств, textfile). Коллекторы с именем хоста и аппаратными адресами выключены.
- **Бэкап** пишет итог каждого запуска в файл метрик формата textfile на хосте (атомарная запись), node_exporter его читает. Сеть контейнера бэкапа не меняется.
- Тексты алертов — по-русски, из статических аннотаций и меток-перечислений. Пользовательских данных в алертах нет.
- Сигналы: недоступность `api` и экспортёра хоста; доля израсходованного дневного бюджета LLM (80 % и 100 %) и всплеск расхода; доля HTTP 5xx; доля ошибок LLM (`unavailable`, `invalid_output`); p95 вызова `rewrite` и TTFC `decode` выше порога; задержка цикла событий; ошибки кэша; сбой заданий аналитики; устаревший или неуспешный бэкап; мало места на диске; мало памяти.
- **Не покрыто (принятый риск):** отказ всего сервера. Alertmanager работает на том же VPS, поэтому о полном отказе он не сообщит. Внешний мониторинг доступности — отдельное решение владельцев.

### 6. Дашборд «Эксплуатация»
Новый ряд «Сервер и алерты»:
- CPU, память, свободное место на дисках;
- возраст последнего успешного ежедневного бэкапа;
- таблица активных алертов (серия `ALERTS` Prometheus, без нового источника данных).

## Альтернативы
- Подпуть `/grafana/` на домене мини-приложения — отклонено (п. 1).
- Дополнительная базовая аутентификация в Caddy перед Grafana — отклонено владельцами: два пароля для ментора. Компенсация — п. 2–4.
- Публичная ссылка на дашборд без входа — отклонено: бизнес-метрики доступны любому, у кого ссылка.
- Оставить туннель как резервный вход — отклонено владельцами: два пути входа и выход Grafana в интернет ради редкого случая.
- Pushgateway для бэкапа — отклонено: лишний сервис. Файл метрик для node_exporter — стандартный способ для пакетных заданий хоста.

## Последствия
- Владелец (релизы и сервер) до релиза:
  - создаёт DNS-запись поддомена;
  - создаёт бота уведомлений и чат владельцев;
  - кладёт два файла секретов и `SP_GRAFANA_DOMAIN` на сервер (RUNBOOK).

  Preflight релиза проверяет это и останавливается, если чего-то не хватает.
- Доступ ментора появляется с первым релизом, в который вошла задача 0049.
- Реестр долга: п. 3 (исключения скана) и п. 5 (алертов нет) закрываются задачей 0049.
- Модель угроз (`03-privacy-and-security.md` §5) дополнена угрозами внешней Grafana.
