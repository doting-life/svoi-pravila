# Task 0001-a — Bootstrap review fixes

Author: CTO (Claude) · 2026-10-03 · Branch: continue on `task/0001-repo-bootstrap`
Verdict on 0001: **CHANGES REQUIRED.** Fix every item below in the same branch. No other changes.

Accepted as-is: Python 3.13.14 (uv has no newer macOS build yet), pinned images and actions (SHAs verified against tags), redaction processor, `CheckReadiness`, import contracts, compose file.

## 1. `environment` must be required (security)
`Settings.environment` defaults to `local`. A server started without `SP_ENVIRONMENT` silently exposes `/docs` and `/openapi.json`. Remove the default; a missing `SP_ENVIRONMENT` is a validation error. Test it.

## 2. Settings read the process environment only
Current `.env` handling (path derived via `parents[3]`, decision from raw `os.environ`, `extra="ignore"`) is fragile and wrong inside the container (the path resolves into `site-packages`).
- Remove all dotenv support from `Settings`: no `env_file`, no `settings_customise_sources` override, no `extra="ignore"`, no `_REPO_ROOT`.
- Local development supplies variables through uv: every Makefile target that runs Python passes the repo-root `.env` to `uv run` with `--env-file` **only when the file exists**; when it does not exist (CI), variables come from the process environment.
- Remove every `_env_file=None` from tests.

## 3. One configuration source for the server process
`http_host`/`http_port` are unused (dead configuration), and `UVICORN_FORWARDED_ALLOW_IPS` is read by uvicorn outside `Settings`, which violates "config.py is the only place that reads the environment".
- Add `forwarded_allow_ips: str` to `Settings` (required, documented in `.env.example`; local value `127.0.0.1`). Remove `UVICORN_FORWARDED_ALLOW_IPS` everywhere.
- In `bootstrap.py`: `load_settings() -> Settings` (the only constructor call of `Settings` in `src/`), `create_application(settings: Settings) -> FastAPI`, and `serve() -> None` that loads settings, builds the app and runs uvicorn programmatically with host, port, `proxy_headers=True`, `forwarded_allow_ips` from settings, `access_log=False` and `log_config=None` (uvicorn must not install its own logging configuration).
- Expose `serve` as the console script `svoi-pravila-api` in `[project.scripts]`.
- Dockerfile: exec-form `ENTRYPOINT ["svoi-pravila-api"]` — no `sh -c`, no hard-coded host/port. Do not copy `pyproject.toml` into the runtime stage.
- README: run the API with `make run` (new target using the console script), not a hand-written uvicorn command line.

## 4. No service locator, no dead code in the composition root
- Remove all `app.state.*` assignments from `bootstrap.py`.
- `create_session_factory` has no consumer until the persistence task: delete it, its export and its test.
- Rewrite `test_bootstrap.py` so it tests behaviour (wiring of probes into `/readyz`, disposal order on shutdown) without `app.state`.

## 5. Alembic must use the project logging and settings
`migrations/env.py` calls `fileConfig(alembic.ini)` — migration logs bypass JSON rendering and redaction — and constructs `Settings` outside the composition root.
- `env.py` obtains settings via `bootstrap.load_settings()` and calls `configure_logging(settings)`.
- Remove all logging sections from `alembic.ini`.
- `script.py.mako`: PEP 604 annotations (`str | Sequence[str] | None`), no `typing.Union`. Verify that a freshly autogenerated revision passes `ruff check`, `ruff format --check` and `mypy` (generate one against a temporary model in a scratch checkout, then discard it; describe the verification in the report — do not commit it).

## 6. Request log must survive exceptions
`RequestLoggingMiddleware` logs nothing when the downstream app raises. Log in a `finally` block; when no response start was sent, the logged status is 500; the exception is re-raised. Add a test with a route that raises.

## 7. Readiness failures must be diagnosable
`CheckReadiness` intentionally hides exception details from the HTTP response, so the cause must reach the logs from the adapters:
- `DatabaseProbe` and `ValkeyProbe` catch failures, log `readiness_probe_failed` with `probe` (name) and `error_type` (exception class name only — never the message, which may contain a DSN), then re-raise the original exception.
- Unit tests for both probes with failing fakes of the engine/client (assert the log event fields and that the exception propagates).

## 8. Tests: one settings factory, deterministic assertions
- Add `tests/factories.py` with `make_settings(**overrides) -> Settings`; replace every hand-built `Settings(...)` in tests with it.
- Integration fixtures build settings from the environment through `bootstrap.load_settings()` — no hard-coded credentials in tests.
- Unreachable-port probe tests: connection refused must yield exactly `ProbeOutcome.FAILED` (not "FAILED or TIMEOUT").

## 9. CI calls the Makefile
The `backend` job must run the Makefile targets (`lint`, `fmt-check`, `typecheck`, `imports`, `test`, `audit`, `migrations-check`) instead of duplicating commands, so local and CI gates cannot drift. Keep the job-level `SP_*` environment (add `SP_FORWARDED_ALLOW_IPS`).

## 10. `.gitignore` hygiene
Remove entries that correspond to no artefact this project produces (`.python-version.bak`, `uv-cache/`).
